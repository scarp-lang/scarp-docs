## What changed

- Exact decimal literals now accept the lowercase suffix `d`: `0.1d + 0.2d` evaluates to `0.3`. Unsuffixed literals remain binary64 floats.
- Tuple members can be replaced at a constant index on a mutable `var` binding, producing a new value rather than changing existing aliases. Compatible numeric tuples now support lexicographic ordering.
- Project creation writes `scarp.project`; existing `Scarp.project` manifests remain readable.
- The experimental Rust host native-object emitter supports pure integer functions with one to six parameters on the Linux x86-64 System V target. It is not a general native compilation CLI.
- Cumulative host admission quotas account for logical UTF-8 string bytes nested in composite values, including repeated occurrences of shared strings.

The interpreter CLI remains the default execution path. Use `scarp exec FILE.srp` or `scarp exec` in a project directory. The latter selects a valid manifest, or the documented default entrypoint; malformed manifests are errors.

## Rust embedding

The new native API adds the symbol `scarp_checked_integer_function` with an object-specific signature. Checked arithmetic failures report a status and source-span index. Loops, calls, contracts, defaults and heap-backed values are excluded. Host invocation ledgers meter interpreter usage and admitted arguments, not operating-system process memory. See [native ELF64 details](https://github.com/scarp-lang/scarp/blob/b1a9347f93540fdf95b0ddecba4adc55a3b4bb98/docs/native-elf64.md) and the [host quota contract](https://github.com/scarp-lang/scarp/blob/b1a9347f93540fdf95b0ddecba4adc55a3b4bb98/docs/development/cumulative-host-quotas-alpha19.md).
