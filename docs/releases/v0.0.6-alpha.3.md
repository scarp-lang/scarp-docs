## Four new numerical functions

| Built-in | Type | Behavior |
| --- | --- | --- |
| `topk(scores, count)` | `integers` | Descending original zero-based indices; earlier index wins ties |
| `topk_values(scores, count)` | `vector` | Selected original scores in matching rank order |
| `softmax_temp(scores, temperature)` | `vector` | Finite temperature-aware probabilities |
| `logsoftmax_temp(scores, temperature)` | `vector` | Finite log probabilities or a diagnostic |

Top-K count zero is valid, including an empty vector; invalid counts report E0033. Signed zero ties preserve original index ordering. Temperature must be a strictly positive finite float. At temperature `1.0`, the result corresponds to the existing softmax form. Resource usage is bounded; very small temperatures can underflow probabilities, but nonrepresentable log probabilities are rejected.

~~~scarp
bind scores = [1.0, 5.0, 5.0, -2.0, 3.0];
print(topk(scores, 3));                // [integer: 1, 2, 4]
print(topk_values(scores, 3));         // [5.0, 5.0, 3.0]
print(topk(softmax_temp(scores, 0.5), 2)); // [integer: 1, 2]
~~~

## Internal compiler work

Private typed scalar IR, definite-initialization verification and test-only interpreter/IR differential checking improve the restricted C11 pipeline. This does **not** ship a general native compiler, `scarp compile`/`scarp build`, LSP, GPU runtime, tensor system, package manager, agent framework or sampling API. No new CLI subcommand or source syntax was added beyond these built-ins. The [previous alpha.2 release](/releases/v0.0.6-alpha.2) documents optional Rust caches.
