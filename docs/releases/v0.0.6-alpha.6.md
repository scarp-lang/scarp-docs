## Three published language foundations

- **Bounded input:** `read_line() -> string` reads an explicitly supplied UTF-8 line. The `exec`, `run`, and project `launch` modes accept **redirected stdin**, not an interactive terminal prompt. [Full contract](/language/program-input-alpha6).
- **Explicit scalar/text operations:** `integer_to_text`, `float_to_text`, `text_to_integer`, `text_to_float`, `text_trim`, and `text_replace`. Parsing is checked and finite; there is no implicit conversion. [Reference](/language/text-foundations-alpha6).
- **Immutable heterogeneous tuples:** `(42, "नमस्ते")`, singleton `(42,)`, types such as `tuple<integer, string>`, literal projection `pair[0]` and structural equality. A `var` may replace a whole tuple of the exact same type. [Limits and examples](/language/tuples-alpha6).

## Exact tagged example and output

The official example is **a two-file source program**, not a standalone one-file snippet. It imports [`examples/modules/input_record.srp`](https://github.com/scarp-lang/scarp/blob/cdf6a3924ec2a36c7beca5a9aec4f01a0bce515e/examples/modules/input_record.srp) to read two lines, trim/convert the first, replace underscores in the second, and return a tuple. See the immutable [source](https://github.com/scarp-lang/scarp/blob/cdf6a3924ec2a36c7beca5a9aec4f01a0bce515e/examples/core_input_tuple.srp), [stdin fixture](https://github.com/scarp-lang/scarp/blob/cdf6a3924ec2a36c7beca5a9aec4f01a0bce515e/examples/core_input_tuple.stdin), and [stdout fixture](https://github.com/scarp-lang/scarp/blob/cdf6a3924ec2a36c7beca5a9aec4f01a0bce515e/examples/core_input_tuple.stdout). The input fixture contains ` 42\r\n नमस्ते_🌍\r\n` (two CRLF-terminated lines). Run it with **v0.0.6-alpha.6**, keeping the referenced module in the same relative location:

~~~scarp
// alpha.6 candidate: redirected UTF-8 input, text conversion and imported tuples.
import "modules/input_record.srp" as records;
bind entry: tuple<integer, string> = records.read();
print(entry);
print(records.describe(entry));
~~~

The tagged interpreter produces the following exact stdout:

~~~text
(42, "नमस्ते 🌍")
42: नमस्ते 🌍
~~~

For a Unix-like shell, after obtaining the source and module directory from the tagged compiler checkout:

~~~sh
scarp exec examples/core_input_tuple.srp < examples/core_input_tuple.stdin
~~~

This fixture demonstrates interpreted execution, **not** native compilation or a persistent interactive prompt. It does not imply that input is available in static `verify` or evaluating `check`.

## Resource limits and compatibility

- **Input:** 65,536 raw bytes per line, 1,048,576 total input bytes and 4,096 selected reads by default. `--max-input-line-bytes`, `--max-input-bytes` and `--max-input-reads` configure the limits. Terminators count toward quotas; terminal-connected input is rejected.
- **Tuples:** 1–32 elements, at most 32 nesting levels, up to 4,096 structural type nodes and a default cumulative 8 MiB tuple-payload limit; `--max-tuple-bytes` adjusts the last limit.
- **Embedders:** `SourceType`, `Value::Tuple` and `ExecutionOptions.max_tuple_bytes` change selected Rust integration contracts; tuple signatures in module inventories use schema 2.
- **Not provided:** empty tuples, destructuring, dynamic tuple indexes, element mutation, BigInt, interactive prompts, a general `scarp compile`, native executables, GPU runtime or stable ABI. The existing narrow Rust C11/ELF64 backends do not accept these input/tuple operations.
