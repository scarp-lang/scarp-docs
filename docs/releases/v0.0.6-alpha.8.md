## Newly shipped: real offline project workflow

- `scarp init DIRECTORY` creates a **new** project using the compiler-owned, declarative `scarp.project` format. It refuses to overwrite an existing directory.
- `scarp run [DIRECTORY]` executes the configured project entrypoint; `scarp verify [DIRECTORY]` checks it without ordinary runtime execution. Single-file `scarp exec FILE.srp` and legacy `Scarp.project` workflows remain supported.
- `scarp project info [--json] [DIRECTORY]` reads validated project metadata without executing the application.
- `scarp test [DIRECTORY]` executes immediate `tests/*.srp` files. `--list` discovers without execution; `--json` writes a structured report; `--filter TEXT` selects a literal case-sensitive filename substring; `--require-tests` fails for empty suites.
- Each test can receive explicit UTF-8 input via a sibling `.stdin` file. The native `assert(boolean, "message");` statement reports source-located **E0065** when false.

These behaviors are published in alpha.8, **not** in alpha.7 or earlier. For an end-to-end exercise use the [calculator tutorial](/tutorials/calculator-alpha8) and [versioned project command reference](/tooling/project-alpha8).

## Compatibility and limits

Legacy `Scarp.project`, `create`, `launch` and `exec` remain available. `assert` becomes a reserved statement word, so rename an existing binding/function with that name. Rust embedders with exhaustive matches on `Statement` and `DiagnosticKind` must handle the new `Assert`/`AssertionFailure` variants.

Test discovery is nonrecursive and capped at **64** immediate `.srp` files. Empty suites succeed by default; add `--require-tests` for CI. The empty `dependencies {}` manifest block is reserved syntax, **not** a package installer. There is no package registry, native `scarp compile` CLI or guaranteed compatibility for every historical program. Assertions are interpreter-only and rejected by the experimental native backends. The main language reference remains pinned to [v0.0.5-alpha.1](/reference/status); features from previous releases are [documented separately](/reference/compatibility).
